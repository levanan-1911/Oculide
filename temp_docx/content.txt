Ứng Dụng Học & Kiểm Tra Lập Trình Trực Tuyến Tích Hợp AI
1. Lớp Giao Diện Người Dùng (Frontend Layer)
Đây là nơi sinh viên và giảng viên tương tác. Tốc độ mượt mà và tối ưu hóa bộ nhớ trình duyệt là ưu tiên hàng đầu.
Công nghệ lõi: React.js (hoặc Next.js) để xây dựng giao diện ứng dụng trang đơn (SPA).
Quản lý trạng thái: Zustand hoặc Redux Toolkit để lưu trữ trạng thái phòng thi, thông báo realtime và dữ liệu bài tập.
Trình soạn thảo Code (IDE): Tích hợp Monaco Editor (lõi của VS Code), hỗ trợ highlight cú pháp, tự động hoàn thành code cơ bản và quản lý đa file.
Xử lý Video/Webcam: Tích hợp SDK của LiveKit để kết nối trình duyệt của người dùng với máy chủ truyền phát video.
Trình bắt sự kiện (Event Trackers): Các đoạn script chạy ngầm trên trình duyệt để lắng nghe API Page Visibility, thao tác chuột/phím (chặn copy-paste), và định kỳ chụp ảnh từ webcam (snapshot) gửi về server.
2. Lớp Dịch Vụ API & Xử Lý Cốt Lõi (Backend API Layer)
Trái tim điều phối toàn bộ logic nghiệp vụ của hệ thống.
Công nghệ lõi: FastAPI (Python).
Xác thực & Phân quyền: Sử dụng JWT (JSON Web Tokens). Quản lý phân quyền chặt chẽ: Giảng viên (tạo phòng, xem tất cả), Sinh viên (chỉ xem đề, nộp bài).
RESTful APIs: Xử lý các thao tác CRUD (Tạo lớp, Thêm đề thi, Quản lý danh sách sinh viên).
WebSockets Hub: Mạng lưới giao tiếp thời gian thực. Nhận và phát sóng (broadcast) các sự kiện như: "Sinh viên A vừa thoát toàn màn hình", "Sinh viên B vừa nộp bài", hoặc tin nhắn chat từ giảng viên.
Cô lập môi trường chấm bài: Python có thư viện docker. Khi nhận code từ sinh viên, hãy dùng Python tạo một container nhỏ, truyền code vào chạy, đặt mem_limit và cờ --network none (ngắt mạng) để chống sinh viên viết code phá server, sau đó tự động xóa container.
Hãy dùng Async/Await triệt để: Vì bạn xử lý hàng chục sinh viên kết nối WebSocket liên tục, nếu viết code đồng bộ (synchronous) bình thường chặn I/O, server sẽ bị treo. Hãy đảm bảo dùng async def cho các endpoint và dùng các thư viện hỗ trợ async.
3. Lớp Truyền Phát Luồng (Streaming & SFU Layer)
Tách biệt hoàn toàn việc xử lý video ra khỏi Backend để tránh làm sập server API.
Công nghệ lõi: LiveKit Server (mã nguồn mở, triển khai độc lập).
Cơ chế hoạt động (SFU): Thay vì trình duyệt của giảng viên phải tải trực tiếp 30 luồng video từ 30 sinh viên (dễ gây treo máy), 30 sinh viên sẽ đẩy video lên LiveKit. LiveKit sẽ tối ưu hóa, hạ độ phân giải nếu mạng yếu, và gom luồng gửi về máy giảng viên một cách trơn tru.
Bảo mật luồng: Backend (FastAPI) sẽ gọi API nội bộ sang LiveKit để tạo phòng, sau đó cấp phát các Token bảo mật cho Frontend. Chỉ những ai có Token mới được vào phòng stream.
4. Lớp AI Giám Sát (AI Proctoring Workers)
Hoạt động song song với API, chuyên xử lý các tác vụ nặng liên quan đến thị giác máy tính.
Luồng xử lý: Cứ mỗi 3-5 giây, Frontend gửi một bức ảnh chụp từ webcam qua WebSocket.
Công cụ phân tích: Các hàm Python tích hợp YOLOv8 (phát hiện vật thể như điện thoại) và MediaPipe (phát hiện khuôn mặt, hướng nhìn của mắt).
Phản hồi: Nếu mô hình AI phát hiện điểm bất thường (ví dụ: mất tích khỏi khung hình), nó lập tức đẩy một sự kiện báo động ngược lại luồng WebSocket để hiển thị màu đỏ trên Dashboard của giảng viên.
Quá 10s không tương tác gì trên màn hình: thì sẽ có thông báo nhắc nhở
5. Lớp Chấm Điểm Tự Động (Auto-Grader Engine)
Cơ quan thực thi mã nguồn của sinh viên một cách an toàn.
Hàng đợi (Message Broker): Redis. Khi có 50 sinh viên cùng nộp bài một lúc, API sẽ không tự chấm ngay mà đẩy 50 bài này vào hàng đợi Redis để tránh quá tải.
Công nhân xử lý (Task Workers): Celery (Python) liên tục lấy bài thi từ Redis ra để xử lý.
Môi trường cách ly (Sandbox): Celery gọi Docker Engine khởi tạo một container siêu nhẹ, đẩy code và test-case vào chạy. Hoàn tất chấm điểm (Pass/Fail, thời gian thực thi) sẽ tự động xóa container và cập nhật điểm số.
6. Lớp Dữ Liệu (Database & Caching Layer)
Lưu trữ toàn bộ thông tin tĩnh và trạng thái động của hệ thống.
Cơ sở dữ liệu chính: SQL Server. Phù hợp để thiết kế cấu trúc dữ liệu chặt chẽ (Relational), lưu trữ thông tin sinh viên, cấu trúc phòng thi, đề bài, và ghi log lịch sử hành vi vi phạm. Việc thiết kế các bảng phụ thuộc, ràng buộc khóa ngoại (Foreign Keys) sẽ đảm bảo tính toàn vẹn dữ liệu.
Bộ nhớ tạm (Caching): Redis lưu trữ các dữ liệu cần truy xuất siêu tốc như Session của người dùng, Token xác thực hiện tại, hoặc danh sách các sinh viên đang online trong phòng.
Với kiến trúc này, khi số lượng người dùng tăng lên, bạn hoàn toàn có thể nhân bản (scale) riêng từng phần (ví dụ: thêm server LiveKit nếu đông người xem video, hoặc thêm server Celery/Docker nếu cần chấm bài nhanh hơn) mà không làm ảnh hưởng đến các phần khác.
